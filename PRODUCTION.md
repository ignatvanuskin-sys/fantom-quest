# Продакшен: что включить и как проверить

Короткий ранбук для вывода сайта в бой. Код, вёрстка, безопасность и API проверены
автоматически (`npm test`, `npm run shots`, `npm run check:deploy`). Ниже — только то, что
зависит от внешних сервисов и решается один раз.

**Главное:** пока не подключено постоянное хранилище, сайт работает в демонстрационном
режиме. Он принимает заявки в память инстанса, не сохраняет их между деплоями и намеренно
не отправляет уведомления — чтобы не создавать обещаний, которые нечем исполнить. Проверить
состояние можно одной командой:

```bash
npm run check:deploy -- https://fantom-quest.vercel.app
```

В конце вывода будет однозначный вердикт: `ГОТОВ К ПРИЁМУ ЗАЯВОК` или `ДЕМО-СТЕНД`.

## 2. Осталось включить

### 2.1. Постоянное хранилище (обязательно для Vercel)

Файловая система на Vercel доступна только для чтения, `/tmp` эфемерный: **постоянное
хранилище там возможно только через Redis по REST.** Сейчас в проекте не подключено ни одного
ресурса (`vercel storage list` — пусто).

Доступные варианты в Marketplace:

```bash
vercel integration discover redis
#   redis              — Official Redis for Vercel
#   upstash/upstash-kv — Upstash, Redis Compatible Database
```

Дальше — один шаг, он требует вашего подтверждения (установка внешнего сервиса со своими
условиями и тарифом):

```bash
vercel integration add upstash/upstash-kv
```

Команда открывает браузер для подтверждения условий; после установки интеграция сама
добавляет в проект переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`. Задавать их вручную
не нужно — код читает и их, и имена Upstash (`UPSTASH_REDIS_REST_URL` / `..._TOKEN`).

**Если ставите Redis вручную** (например, свой аккаунт Upstash), задайте две переменные.
Учтите проверенный подводный камень: в PowerShell `vercel env add` **не принимает значение
через конвейер** — вместо значения записывается имя переменной. Надёжные способы: панель
Vercel (Project → Settings → Environment Variables) или REST API Vercel. После добавления
обязательно перепроверьте значение:

```bash
vercel env pull .env.production.local   # и глазами убедиться, что значение, а не имя
```

После подключения хранилища `demoMode` выключается сам: `persistentStorage` становится `true`,
и `MOCK_MODE` перестаёт форсироваться.

### 2.2. Уведомления о заявках

Переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` уже заведены в проекте. Порядок:

1. Создайте бота у `@BotFather`, получите токен.
2. Напишите боту любое сообщение, откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и возьмите `chat.id`.
3. Пропишите оба значения в переменных окружения проекта.
4. Переключите `MOCK_MODE=false` **только после** того, как отправите тестовую заявку и
   увидите сообщение в чате. Пока `MOCK_MODE=true`, заявка сохраняется, но бизнесу не уходит.

Альтернативы вместо Telegram: `NOTIFY_WEBHOOK_URL` (POST с JSON заявки) или почтовый
HTTP-релей (`NOTIFY_EMAIL_TO`, `NOTIFY_EMAIL_FROM`, `EMAIL_HTTP_ENDPOINT`, `EMAIL_HTTP_TOKEN`).
Достаточно одного рабочего канала.

### 2.3. Админка

`ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET` уже стоят в Production, значения лежат в
`.admin-credentials.txt` (файл в `.gitignore`). Перед публикацией смените пароль на свой:

```bash
node -e "console.log(require('crypto').randomBytes(18).toString('base64url'))"
```

## 3. Развёртывание

### Vercel

```bash
npm test                                  # 63 теста + проверка kv-драйвера
git push origin main                      # оба проекта собираются автоматически
npm run check:deploy -- https://fantom-quest.vercel.app
```

Ожидаемый финал: `Проверок: 43, провалено: 0` и вердикт `ГОТОВ К ПРИЁМУ ЗАЯВОК`.

**Внимание: сайт развёрнут в двух проектах Vercel.** `vercel project ls` показывает:

| Проект | Продакшн-адрес | Связь с папкой |
|---|---|---|
| `fantom-quest` | https://fantom-quest.vercel.app | к этой папке привязан `vercel link` |
| `phantom` | https://phantom-nine-delta.vercel.app | этот адрес проверял внешний UX/CRO-аудит |

Оба собираются из одного репозитория, поэтому `git push` обновляет оба, а `vercel --prod`
из этой папки — только `fantom-quest`. Это создаёт дубликат сайта: два адреса отдают одно и то
же содержимое, и на каждом `canonical` указывает на него самого (проверено по `robots.txt` и
`sitemap.xml` обоих адресов). Для поисковика это две разные страницы с одинаковым текстом.
Решение — оставить **один** проект, второй удалить или отключить у него автосборку.

Заодно стоит задать `SITE_URL` явно (`https://<выбранный-домен>`): сейчас переменная пустая,
поэтому адрес подставляется платформенный и меняется вместе с адресом деплоя.

### Обычный сервер (VPS) — путь без внешних сервисов

Файловый драйвер полностью рабочий и постоянный, если у сервера есть диск. На Vercel он
непостоянен, на VPS — постоянен, поэтому этот путь не требует ни Redis, ни Marketplace.

```bash
SITE_URL=https://fantom.kz \
DATA_DIR=/var/lib/fantom \
ADMIN_PASSWORD='…' \
MOCK_MODE=false \
TELEGRAM_BOT_TOKEN='…' TELEGRAM_CHAT_ID='…' \
node server.js
```

Процесс держите под `systemd` или `pm2` (`restart: always`), каталог `DATA_DIR` — на диске,
бэкап — `data/db.json` и `data/audit.log.jsonl` (см. README, раздел «Бэкап и откат»).

## 4. Проверка после включения

1. `npm run check:deploy -- <адрес>` → `Проверок: 43, провалено: 0`, вердикт `ГОТОВ`.
2. Оформите **настоящую тестовую заявку** через сайт.
3. Убедитесь, что она видна в админке (`/admin`) и пришла в Telegram/webhook.
4. Нажмите «Подтвердить» в админке и проверьте страницу `/booking/status` по номеру заявки.
5. Сделайте тестовый деплой и убедитесь, что тестовая заявка **осталась** — это и есть
   проверка постоянного хранилища на живой платформе.
6. Удалите тестовую заявку через админку.

## 5. Что решает владелец

Не блокирует запуск, но влияет на доверие и на рекламу детских режимов — подробный разбор в
`AUDIT.md`, раздел 3: одно публичное название локации, один основной Instagram, safety-условия
(возрастные границы, стоп-слово, перенос брони), юридическая проверка `/privacy`, доплата за
7+ игроков в «Level 2» и подтверждение арифметики тарифов для авторасчёта итоговой суммы.

## 6. Известные ограничения

Честно, чтобы не было сюрпризов на живом трафике. Ни одно из них не мешает принимать заявки,
но знать о них стоит.

* **Ограничитель частоты и ключи идемпотентности живут в памяти инстанса.** На Vercel
  инстансов несколько, поэтому лимит «8 заявок с адреса за 10 минут» действует на каждый
  инстанс отдельно. Двойной брони из-за этого не будет: слот защищён распределённой
  блокировкой и состоянием слота в Redis, вторая заявка на то же время получит `409`.
  Если понадобится жёсткий общий лимит — счётчики переезжают в тот же Redis (интерфейс
  `src/lib/ratelimit.js` это позволяет, как и переход хранилища на PostgreSQL).
* **Уведомления не повторяются.** Если Telegram недоступен в момент заявки, сообщение не
  уйдёт повторно — заявка останется в админке. Для потока заявок в сутки этого достаточно;
  при росте стоит добавить очередь повторов.
* **Один процесс обслуживает и сайт, и админку.** На VPS при нагрузке поднимайте несколько
  инстансов — драйвер `file` для этого не подходит, нужен `kv` или PostgreSQL.

## 7. Если что-то пошло не так

```bash
vercel ls                                  # список сборок
vercel rollback                            # откат на предыдущий деплой
vercel logs <адрес-деплоя>                 # логи продакшна
```

Данные при откате не теряются: они лежат в Redis (или в `DATA_DIR` на VPS), а не в сборке.
Если после включения хранилища заявки перестали появляться в админке — первым делом
проверьте `GET /api/health`: `storage.persistent` должен быть `true`, `writesEnabled` — тоже.

# Визуальный и ручной чек-лист

Автотесты (`npm test`) покрывают API, слоты, ночной график, валидацию, атомарность,
админку и базовые требования к вёрстке. Этот файл — то, что нужно проверить глазами и
руками перед публикацией. Он же — источник скриншотов для приёмки.

Сервер: `npm start` → `http://localhost:3000`.

---

## 0. Что уже снято автоматически

```bash
npm start                    # терминал 1
npm run shots                # терминал 2 — полные скриншоты + замеры переполнения
npm run shots:first-screen   # читаемый предпросмотр первых экранов
npm run shots:probe          # геометрия конкретной страницы без снимков
```

Результат: `tests/artifacts/*.jpg`, `tests/artifacts/first-screen/`, отчёты
`layout-report.md` и `layout-report.json`. Последний прогон: **100 замеров, 0 переполнений**.

Правила веб-интерфейса проверяет `npm run qa:ui` (скрипт `tests/ui-rules.js`): доступные имена,
подписи полей, видимый клавиатурный фокус, тёмная тема, отклик на касание, переносы заголовков.

Отдельно есть `npm run qa:browser` — работа в реальном браузере: клики, ввод, крайние случаи
записи, консоль, сеть, цели нажатия, цена на разных экранах, CLS и LCP. Скрипты покрывают все
ширины из списка ниже, сами проходят мастер записи и проверяют слой движения. Ниже — только то,
что они проверить не могут.

## 1. Скриншоты вручную (реальные устройства)

| Ширина | Что смотреть |
|---|---|
| 320 / 360 / 375 / 390 / 430 | `/`, `/booking`, `/quests`, `/prices`, `/gallery`, `/faq`, `/contacts` |
| 768 / 1024 | те же страницы: сетка каталога, галерея, двухколоночные блоки |
| 1280 / 1440 / 1920 | те же страницы + `/reviews`, `/privacy`, `/admin` |

Мобильные ширины сняты автоматически, но **реальный телефон** нужен для проверки клавиатуры,
инерционного скролла и «липких» блоков.

Что проверять на каждом скриншоте:

- [ ] Нет горизонтального скролла (`document.documentElement.scrollWidth <= innerWidth`)
- [ ] H1 не обрезан, переносы строк читаемые
- [ ] Hero: адрес, «60 минут», «09:00–02:00» и обе CTA видны без скролла на 390 px
- [ ] Плашки «Уточняется» / «Нужно подтвердить» видны и не выглядят как ошибка вёрстки
- [ ] **Никаких технических плашек**: нет слов о режиме стенда, хранилище, `MOCK_MODE`,
      «заявка не сохранится», «уведомления не отправляются». Посетитель не должен видеть
      внутреннее устройство — только рабочий сайт
- [ ] Контраст текста достаточный (минимум 4.5:1 для основного, 3:1 для крупного)
- [ ] Кнопки не меньше 44×44 px, легко нажимаются пальцем
- [ ] На мобильном меню-гамбургер открывается и закрывается, ссылки ведут верно
- [ ] Sticky header не перекрывает контент при скролле

Отдельно проверить:

- [ ] Sticky-summary в записи не перекрывает последнее поле формы на 390 px
- [ ] Клавиатура не закрывает активное поле на реальном телефоне
- [ ] Логотип, favicon и OG-превью отображаются (проверить превью ссылки в Telegram/WhatsApp)

## 2. Главная страница: секции

Проверить, что секции идут по порядку и каждая несёт смысл, а не декорацию:

- [ ] Hero → бегущая строка фактов → доверие (рейтинг 2ГИС, отзывы, фото)
- [ ] Ближайшие игры: реальные свободные слоты, а не заглушки
- [ ] Каталог программ: фильтры работают, каждый пакет — с реальной ценой или «Уточняется»
- [ ] Персонажи: только подтверждённые (Самара, Монахиня, клоун Эдди); у кого нет кадра — нет фото
- [ ] Шкала страха: 5 режимов из таблички локации
- [ ] История, «что входит», галерея, Instagram, цифры, отзывы
- [ ] «Как проходит», «что знать заранее», запись, локация, FAQ, финальный CTA
- [ ] Нигде нет выдуманных чисел: ни «10 000 игроков», ни таймера срочности, ни фейковых скидок

## 3. Мастер записи (5 шагов)

- [ ] Шаг 1 → 2 → 3 → 4 → 5 → 6 переключается, индикатор шагов подсвечивается
- [ ] Шаг 1 без выбранной программы вперёд не пускает и объясняет почему
- [ ] Шаг 2 без даты вперёд не пускает; видно количество свободных слотов в дне
- [ ] Шаг 3 без времени вперёд не пускает
- [ ] Ночные слоты помечены «после полуночи», в summary то же самое
- [ ] Шаг 4: состав ограничен диапазоном пакета (мимо — понятная ошибка)
- [ ] Шаг 5: обязательны имя, телефон и согласие; honeypot пуст
- [ ] Шаг 6: сводка совпадает с тем, что реально уйдёт на сервер
- [ ] Summary (справа на десктопе, снизу на мобильном) обновляется сразу:
      программа, дата, время, состав
- [ ] В summary цена показана как «Уточняется у администратора» — не выдуманное число
- [ ] Кнопка называется «Отправить заявку», а не «Оплатить»
- [ ] Успех: номер заявки, данные, текст про связь администратора, кнопка WhatsApp, телефон,
      «Проверить статус заявки»
- [ ] Ошибка сети: сообщение понятное, **введённые данные остались в форме**
- [ ] Занятый слот: сообщение «Время только что заняли», возврат на шаг с временем,
      сетка слотов перезагружается, данные сохранены
- [ ] Выход из «успеха» и повторная запись на другое время работает

## 4. Клавиатура и скринридер

Полный проход только с клавиатуры (`Tab`, `Shift+Tab`, `Enter`, `Space`, стрелки):

- [ ] Первый `Tab` — skip-link «Перейти к содержанию»
- [ ] Все интерактивные элементы получают видимый фокус
- [ ] Меню доступно, `aria-expanded` меняется
- [ ] Шаги мастера: `Tab` попадает в поля и кнопки линейно, ничего не пропущено
- [ ] Слоты: `Tab` заходит в группу, стрелки ←→↑↓ перемещают выбор, `Enter`/`Space` выбирают
- [ ] `aria-checked` меняется у выбранного слота
- [ ] Галерея: кнопки открывают просмотр, `Escape` закрывает, фокус возвращается на кадр
- [ ] Honeypot-поле не попадает в tab-порядок
- [ ] Сообщения об ошибках и успехе зачитываются (`aria-live`)
- [ ] `<details>` FAQ раскрываются с клавиатуры

Скринридер (NVDA / VoiceOver):

- [ ] H1 объявляется один раз
- [ ] Поля имеют читаемые подписи и подсказки
- [ ] Ошибки полей связаны с полями (`aria-describedby`)
- [ ] Кнопки WhatsApp/телефон читаются осмысленно

## 5. Движение, звук, производительность

Слой движения живёт в `public/effects.css` и `public/effects.js` отдельно от дизайн-системы.
Концепция — «прямая трансляция из подвала»: визир кадра, свет по контуру, фонарь за курсором,
точечное табло цифр, появление блоков как переключение канала.

Что уже проверяет `npm run shots` (раздел «Слой движения» в `layout-report.md`):
сколько блоков осталось невидимыми после полной прокрутки, реагируют ли фонарь и магнит
на курсор, что нарисовано на canvas, формат табло времени и что при `prefers-reduced-motion`
видно **всё** без исключений. Ниже — то, что проверяется глазами и руками.

- [ ] При системном `prefers-reduced-motion: reduce` движение отключено: табло времени не тикает,
      развёртка стоит, поле чернил и фонарь не создаются вовсе, плавный скролл выключен
- [ ] Ни один блок не остаётся невидимым, даже если дописать в адресной строке мусор
      и перезагрузить страницу
- [ ] Появление блоков не раздражает при быстрой прокрутке: задержка внутри группы не больше
      секунды, повторного появления при возврате вверх нет
- [ ] Фонарь за курсором не мешает читать: текст под ним остаётся контрастным
- [ ] Свет на карточках и луч по контуру кнопки видны только при наведении, на тач-экране их нет
- [ ] Анимируется только `transform`, `opacity` и `filter` — в профилировщике нет пересчёта вёрстки
- [ ] Нет вспышек, jumpscare, дыма и фейковой срочности; таймеров «осталось 5 минут» не существует
- [ ] Анимации останавливаются, когда блок ушёл с экрана, и когда вкладка неактивна
- [ ] Звук **не** стартует при загрузке страницы и при скролле
- [ ] Кнопка звука по умолчанию «выключен»
- [ ] После включения звука громкость плавно нарастает, после выключения — убирается
- [ ] Галерея и изображения грузятся лениво, в критическом пути: HTML, CSS, `app.js`, иконка;
      `effects.css` и `effects.js` подключены после них и не блокируют первый экран
- [ ] Ни один оверлей не блокирует hero, меню, скролл и кнопку записи

## 6. Конверсия: путь из Instagram

Гость пришёл из сторис и не читает лендинг целиком. Проверить по секундам:

| Время | Что он должен понять | Проверка |

| 5 с | это хоррор-квест в Усть-Каменогорске, есть кнопка записи | H1, город, CTA в первом экране |

| 30 с | можно ли в его дату и время | блок ближайших слотов / шаг 2 мастера |
| 60 с | как записаться и что будет дальше | мастер: 5 шагов без тупиков |
| 90 с | это не развод: реальные фото, отзывы, адрес, рейтинг | галерея, отзывы 2ГИС, локация |

- [ ] Телефон и WhatsApp видны без поиска
- [ ] Ни один шаг мастера не заканчивается тупиком без объяснения
- [ ] Никаких всплывающих окон, перекрывающих CTA

## 10. Граничные сценарии

- [ ] Игровой день, где часть слотов уже прошла: прошедшие помечены и недоступны
- [ ] Ночной слот 00:00 и 01:00 можно забронировать, в подтверждении — «после полуночи»
- [ ] Заявка ровно на 01:00 принимается (игра заканчивается в 02:00)
- [ ] Заявка на 02:00 отклоняется
- [ ] Переход через полночь при смене даты в селекте не путает игровой день
- [ ] Две вкладки бронируют один слот — вторая получает понятную ошибку
- [ ] Медленная сеть: кнопка «Отправляем…» блокируется, дублей заявки нет
- [ ] Сервер выключен во время отправки — сообщение об ошибке и сохранённые данные
- [ ] `MOCK_MODE=false` проверен на отдельном стенде (не на боевых данных)

## 11. Приёмка (Definition of Done)

Сайт готов, если новый посетитель без объяснений:

- [ ] понимает за 5 секунд: это хоррор-квест Fantom, где он находится и сколько длится игра;
- [ ] видит, как связаться, и находит кнопку записи;
- [ ] выбирает реальный слот меньше чем за минуту;
- [ ] отправляет заявку без потери данных;
- [ ] получает номер заявки и понимает, что будет дальше;
- [ ] **не видит ни одного слова про внутреннее устройство сайта** — режим стенда,
      хранилище, уведомления и состояние базы остаются в `README.md`, `.env.example`
      и `/healthz` для оператора;
- [ ] не пугается интерфейса: ни одна анимация не прячет CTA, ни один слот не создаёт
      ложную срочность, ни одна цифра не расходится между UI, записью, разметкой и источником.
